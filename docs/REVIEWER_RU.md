# Инструкция кейс-холдеру: запуск, проверка, автодеплой

Поставка на 25.10.2026. Основное демо — пять экранов `demo/ff`, а не старая инженерная консоль на порту 8080. Обучение автоматически не выполняется.

## Чистый запуск

1. Установить Git, Docker Engine + Compose ≥2.20 либо Docker Desktop с Linux containers. Проверка: `docker version`, `docker compose version`. Проверенная архитектура контейнеров — Linux x86_64.
2. Клонировать репозиторий:

```bash
git clone https://github.com/Noizicrafty/GreatHanDetect.git
cd GreatHanDetect
docker compose up -d --build --wait
```

3. Открыть http://127.0.0.1:8090/. Первый build скачивает зависимости и `last.pt` из фиксированного Release с проверкой SHA-256. Python на хосте и ручное размещение весов не нужны. Сборка может занять несколько минут; далее используются cache и готовый образ.
4. Запустить проверку настоящей модели:

```bash
docker compose --profile check run --rm check
```

Успех — `passed: true` и exit code 0. Проверяются пять страниц, локальные MediaPipe assets, PDF/кириллица, открытие XLSX и ZIP, реальный CPU-инференс положительного примера и пустого изображения, отсутствие изменений журнала. Healthcheck отдельно проверяет доступность HTTP и файлов модели, а не качество детектора.

## Проверка руками

| Действие | Ожидаемый результат |
|---|---|
| Открыть главную | Переход на страницу трансляций, без directory listing |
| Запустить демонстрационные камеры | Движущиеся предоставленные записи с готовыми рамками, помечены DEMO |
| «Проверить кадр» → готовый пример | Предсказание реальной модели, найденная сигарета, новый кадр в журнале |
| Повторить тот же кадр | Нет дубликата, сохраняется решение оператора |
| Подтвердить / отклонить → обновить страницу | Решение остаётся в SQLite и отражается в аналитике |
| Скачать PDF | Актуальный журнал, кириллица и переносы; не исходный статичный PDF |
| Фильтр → скачать XLSX | Данные соответствуют фильтру |
| ZIP кадров | Только подтверждённые реальные кадры, разметка — псевдометки модели |
| «Веб-камера» → разрешить | Прямой эфир и отдельно последний обработанный кадр |
| Остановить / Escape / скрыть вкладку | Видеотреки освобождены, запросы прекращены |
| CPU без TPU | Обычный CPU-режим работает; TPU отмечен недоступным |
| Пересоздать контейнер | Журнал и выбранные кадры сохраняются в named volume |

Детекция сигареты около губ не доказывает факт курения. Реальные отрицательные/положительные видео для оценки event precision/recall пока не предоставлены. Сохранение кадра с камеры включает CPU-перепроверку; обычные кадры не сохраняются.

## Управление и диагностика

```bash
docker compose ps
docker compose logs --tail 100 demo
docker compose restart demo
docker compose down
```

`down` сохраняет named volume. `down -v` удаляет историю; используйте только для намеренного сброса.

- Порт занят: скопировать `.env.example` в `.env`, задать `DEMO_PORT=8091`, пересоздать `docker compose up -d`. Чекер использует внутренний порт и продолжит работать.
- Docker daemon недоступен: запустить Docker Desktop/Engine, проверить режим Linux containers.
- Build не скачивает веса: проверить доступ к GitHub Releases и PyTorch/PyPI, повторить build. Ошибка хеша останавливает сборку, случайные веса не загружаются.
- Камера недоступна по внешнему HTTP-IP: браузер требует HTTPS или localhost. Использовать HTTPS reverse proxy либо `ssh -L 8090:127.0.0.1:8090 user@server`, затем открыть localhost на своём компьютере.
- CPU первый кадр долгий: происходит загрузка модели в память; дальнейшие кадры используют один resident worker. CPU-режим ограничен двумя запросами в секунду.

## Подключение LinQ TPU

TPU — удалённый сервис организаторов; Docker сам не создаёт аппаратный TPU и не содержит проприетарный SDK/codec/VPN. Доступ к сети брокера, данные AMQP и файл программы на сервере нужны отдельно. Пруфы существующего запуска доступны без подключения: [отчёт](TPU_RESULTS_RU.md), [архив](https://github.com/Noizicrafty/GreatHanDetect/releases/download/models-2026-10-25/GreatHanDetect_TPU_proofs_2026-10-25.zip).

### Вариант A: уже работающий JPEG-сервис

Указать в `.env` `LINQ_UPSTREAM_URL=http://адрес-доступный-из-контейнера:8094` и пересоздать `docker compose up -d`. Это сервис `tools/serve_webcam_tpu.py`, не AMQP endpoint и не адрес Jupyter UI. Он должен отвечать на `/api/demo/linq-health` и `/api/demo/webcam/linq`. Адрес фиксирован конфигурацией, не принимается из запросов пользователя. Для localhost хоста контейнера учитывайте Docker networking; `127.0.0.1` внутри контейнера означает сам контейнер.

### Вариант B: свой TPU-sidecar

1. Получить от организаторов `tpu_pycloud_format-*.whl` и поместить в `vendor/codec/`. Wheel игнорируется Git. Официальный SDK компилятора для исполнения готовой программы не требуется.
2. Обеспечить доступ **из Docker-контейнера** к AMQP брокеру (VPN/маршрутизация). VPN на Windows-хосте не гарантирует такую маршрутизацию для Docker Desktop.
3. Скопировать `.env.example` в `.env`. Заполнить `LINQ_AMQP_USER`, `LINQ_AMQP_PASSWORD`, host/port/exchange/vhost и `LINQ_REMOTE_PROGRAM`. Последний — абсолютный путь `/auto/cache/.../*.tpu` на файловой системе исполнителей организатора, а не локальный путь Windows.
4. Программа O1 автоматически скачивается в контейнер и проверяется по хешу. **Та же программа** должна существовать на удалённом пути: загрузить [O1.tpu](https://github.com/Noizicrafty/GreatHanDetect/releases/download/models-2026-10-25/smoking_trained26_416_o1.tpu) в доступный исполнителю каталог. Для командного стенда ранее использовался путь `/auto/cache/hackathon61961/smoking_trained26_416_o1.tpu`.

```bash
docker compose -f compose.yaml -f compose.tpu.yaml up -d --build --wait
docker compose -f compose.yaml -f compose.tpu.yaml --profile check run --rm check --tpu
```

В UI выбрать «LinQ TPU · O1». Дополнительный чекер требует **реального AMQP ответа** с backend `linq_amqp`, ожидаемыми SHA-256 и request ID. Если codec/маршрут/программа отсутствуют, тест завершается ошибкой, CPU не подставляется. HTTP health TPU-sidecar подтверждает только загрузку сервиса/проверку локальной программы; удалённое исполнение подтверждает именно `check --tpu`.

Контейнер TPU не публикует свой порт на хост; доступен только демо через внутреннюю сеть Compose. Препроцессинг/NMS остаются на CPU. Сервис держит две AMQP-сессии, каждая принадлежит отдельному потоку; очередь входящих кадров ограничена двумя слотами.

Для возврата к CPU: убрать overlay из команды, выполнить `docker compose up -d --remove-orphans`. В `.env` очистить `LINQ_UPSTREAM_URL`, если он был задан вручную.

## Автодеплой

Базовый Compose уже собирает и запускает все компоненты CPU-демо, автоматически перезапускает контейнер после рестарта Docker, проверяет health и хранит историю отдельно от образа.

На подготовленном сервере с чистым клоном ветки `main` обновление и проверка выполняются одной командой:

```bash
bash deploy/linq-demo/autodeploy.sh
```

Скрипт проверяет незакоммиченные изменения, делает `git pull --ff-only`, `up --build --wait`, затем настоящий smoke check. Данные не удаляет. Это обновление с кратким пересозданием контейнера, не zero-downtime или автоматический rollback.

В GitHub Actions есть два workflow: **Demo — clean Docker deployment** (push/PR/manual: чистая сборка + smoke check) и **Deploy demo over SSH** (ручной запуск, чтобы случайный push не менял внешний сервер). Для последнего один раз подготовить серверный клон/права Docker и environment `demo`, задать secrets `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`, variable `DEPLOY_PATH` (абсолютный путь к клону). Fingerprint хоста проверяется заранее и фиксируется в known_hosts; проверки SSH не отключаются. Эти secrets в репозитории не заполнены и не публикуются.

Для публичного доступа задать `PUBLIC_ORIGIN=https://свой-домен` в `.env`, а HTTPS reverse proxy направить на loopback-порт Compose. Существующий публичный стенд использует [Nginx](../deploy/linq-demo/nginx.conf); домен и сертификат в этом файле — пример конкретного стенда. Основной Compose не выпускает сертификат автоматически и не привязан к нашему домену.

## Состав поставки и границы проверки

- Код и frontend — в Git; MediaPipe assets локальны, CDN во время обработки не нужен.
- Checkpoint, `.tpu` и proof ZIP — [фиксированный Release](https://github.com/Noizicrafty/GreatHanDetect/releases/tag/models-2026-10-25), [SHA-256](evidence/model_artifacts.json).
- SDK/codec, VPN, ключи/пароли и полный датасет — вне Git.
- Не начинается обучение; PTQ-компиляция также не входит в старт Compose.
- PPE/бег исходного макета — DEMO. Отсутствие производственных видеотестов и ухудшение части детекций PTQ отмечены в отчёте.
- Инженерная консоль `python -m greathan` остаётся доступной по отдельной [инструкции](DEPLOYMENT_RU.md); её история и порты не смешиваются с демо.
