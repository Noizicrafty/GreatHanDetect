# Локальное демо из презентации

Адрес: **http://127.0.0.1:8090/**. Пять исходных страниц из предоставленного `final_frames.rar`: трансляции, мониторинг, аналитика, уведомления и отчёт. Оформление и фото сохранены. Добавлены действия, которые отсутствовали у макета.

## Запуск

Для чистого клона используйте `docker compose up -d --build --wait` из [README](../README.md). Подробная проверка и подключение LinQ: [инструкция кейс-холдеру](REVIEWER_RU.md). Ниже описан прежний ручной запуск без Docker.

На подготовленном компьютере запустить [START_PRESENTATION_DEMO_WINDOWS.bat](../START_PRESENTATION_DEMO_WINDOWS.bat) из корня репозитория. Он использует отдельную `.venv-demo`. Сервер слушает только `127.0.0.1`. Интернет, VPN и LinQ для демонстрации не нужны. Если сервер уже работает, достаточно открыть ссылку выше.

Для ручного запуска:

```powershell
.venv-demo\Scripts\python.exe tools\run_presentation_demo.py --port 8090
```

Другая история и порт: `--data results/presentation-demo-other --port 8091`. Завершение при ручном запуске — Ctrl+C в окне сервера. Открытая вкладка браузера не является серверным процессом.

## Что можно показать

1. **Трансляции:** включить/остановить две реальные анимации из пользовательского `samples.gif`. Это предоставленные записи с готовой разметкой, не живые камеры и не результат запуска наших PPE-моделей.
2. **Мониторинг:** посмотреть карточки, изображения и очередь. Все события из презентации явно обозначены DEMO.
3. **Уведомления:** выбрать событие, подтвердить либо отклонить. Решение сохраняется в SQLite и после обновления страницы отражается в аналитике и PDF.
4. **Аналитика:** фильтровать категории, искать, сортировать столбцы, скачивать кадры и настоящий `.xlsx` с учётом фильтров.
5. **Отчёт:** увидеть и скачать текущий PDF. Предпросмотр и скачивание используют один генератор; исходный статичный PDF из презентации не подставляется вместо актуального журнала.
6. **Проверить кадр:** загрузить JPG/PNG/WEBP или нажать «Использовать готовый пример». Выполняется реальный локальный PyTorch CPU-инференс сохранённых весов YOLOv8n после 26 эпох. Обучение и TPU не запускаются.
7. **Кадры для датасета:** ZIP содержит только подтверждённые оператором кадры обученного checkpoint. Боксы являются автоматическими **псевдометками**, не исправленной человеком эталонной разметкой. DEMO-кадры исключены.

При повторной проверке того же кадра с теми же весами новое событие не создаётся; прежнее решение сохраняется. Обнаружение сигареты/дыма/вейпа создаёт «Признаки курения · кадр» и не выдаётся за подтверждённый временной эпизод.

«Сбросить примеры» восстанавливает только события презентации. Реальные результаты checkpoint сохраняются.

## Файлы

- `demo/ff/` — интерфейс и пользовательские материалы.
- `tools/run_presentation_demo.py` — HTTP, SQLite, решения, PDF/XLSX/ZIP.
- `tools/presentation_predict.py` — отдельный процесс только для inference.
- `results/presentation_demo/demo.sqlite3` — локальный журнал.
- `results/presentation_demo/uploads/` — принятые изображения, реальные предсказания и provenance.
- `results/presentation-demo.stdout.log`, `presentation-demo.stderr.log` — логи текущего фонового экземпляра.

Номер рабочего демо-порта 8090 отличается от основного приложения GreatHanDetect на 8080/8081. Демонстрационная история не смешивается с прежними испытаниями LinQ.

## Восстановление окружения

Для интерфейса нужны Python 3.12 и `requirements/demo.txt` (Pillow, reportlab, openpyxl). Launcher создаёт `.venv-demo`, если её нет. Веса передаются отдельно и по умолчанию читаются из `results/training_roboflow_v4/smoking/weights/last.pt`.

Для работы checkpoint — отдельная `.venv-model`:

```powershell
py -3.12 -m venv .venv-model
.venv-model\Scripts\python.exe -m pip install torch==2.9.1 torchvision==0.24.1 --index-url https://download.pytorch.org/whl/cpu
.venv-model\Scripts\python.exe -m pip install -r requirements\demo-model.txt
```

Можно указать собственный Python через `--model-python` и checkpoint через `--checkpoint`. Демонстрация подготовлена для сохранённых весов после 26 эпох; перенос других классов и архитектур требует отдельной проверки. При отсутствии окружения интерфейс доступен, кнопка модели отключена.

## Проверки

Серверные интеграционные проверки: `tools/test_presentation_demo.py`, отдельный временный журнал. Для PDF-проверок дополнительно требуется PyMuPDF. Проверяются HTTP, ресурсы, сохранение решений, фильтры экспорта, PDF/кириллица/переносы/параллельные запросы/пустые данные, реальный inference, дубли, ZIP и ошибочные запросы. Результат — `results/presentation_demo_qa/backend_qa.json`.

Браузерная проверка выполнялась в Microsoft Edge на пяти страницах, на ширинах 1600, 390 и 320 px. Отдельно проверен файл, скачанный кнопкой PDF, а не только ответ API. Полная матрица: [QA локального демо](DEMO_QA_RU.md).

## Происхождение материалов

`final_frames.rar` и `samples.gif` предоставлены пользователем в Downloads. Архивные GIF оказались одно-кадровыми: кнопки настоящего воспроизведения используют 29-кадровые фрагменты `samples.gif`; пример бега показывается как статичный кадр. Материалы включены в публичное хакатон-демо по запросу команды; их происхождение — предоставленная презентация, а не собственные съёмки.

Готовый пример проверки модели взят из Richie Lab / smoking-tasfx v4 (CC BY 4.0 по экспорту), см. [атрибуцию](THIRD_PARTY_NOTICES.md). Заявления презентации о 98%/78% точности и задержке <1 с не используются как подтверждённые показатели модели.

## Веб-камера

В верхней панели доступна кнопка «Веб-камера». HTTPS или localhost → Запустить → разрешить видеокамеру. Контур губ сопоставляется с сигаретой существующего checkpoint; обычные кадры не сохраняются. Подробности и ограничения: [WEBCAM_RU.md](WEBCAM_RU.md).
