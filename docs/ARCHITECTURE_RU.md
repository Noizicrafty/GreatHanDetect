# Архитектура и API

## Поток данных

```text
VideoSource -> Vision -> ONNX CPU / LinQ AMQP
            -> raw-head decode + NMS -> IoU tracker
            -> ZoneRule / SmokingRule -> EpisodeManager
            -> evidence JPEG -> SQLite event + notification outbox
            -> HTTP API -> operator UI + display acknowledgement
```

`video.py` управляет временной шкалой и пропуском кадров; `inference.py` объединяет модели и preprocessing; `backends.py` реализует ONNX и AMQP; `contracts.py` проверяет тензоры. `tracking.py` сопоставляет людей один к одному. `rules.py` подтверждает и завершает эпизоды, различает отрицательное и неизвестное наблюдение. `pipeline.py` связывает обработку, кадры и метрики.

`store.py` хранит журнал/уведомления в SQLite WAL. `server.py` предоставляет локальный HTTP API, `web/` — операторский интерфейс. `capabilities.py` описывает дополнительные сценарии и явно маркирует DEMO. `instance_lock.py` предотвращает одновременное использование одной истории разными процессами.

## Событие

Содержит ID эпизода, камеры, зоны, прогона и трека, тип, source timestamps, время подтверждения, состояние жизненного цикла, путь кадра, backend, версии модели/конфигурации, confidence и решение оператора. Удлинение нарушения обновляет эпизод; новое подтверждённое нарушение после завершения получает новый ID. Короткое перекрытие не должно создавать дубль. `lost` означает потерю наблюдения, а не доказанное окончание нарушения.

Кадр сохраняется до записи события; событие и уведомление создаются транзакционно. После перезапуска незавершённые исторические эпизоды помечаются прерванными, журнал сохраняется. Подтверждение показа браузером идемпотентно.

## Основные HTTP-маршруты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/status`, `/api/config`, `/api/capabilities` | Состояние, настройки, сценарии |
| GET | `/api/events`, `/api/events/<id>` | Журнал и событие |
| GET | `/api/notifications` | Уведомления с курсором |
| GET | `/api/export.csv` | Экспорт фильтрованной истории |
| GET | `/api/frame.jpg`, `/api/source-preview.jpg` | Текущий кадр и предпросмотр |
| GET | `/evidence/<id>.jpg` | Кадр-доказательство |
| GET | `/api/runs`, `/api/diagnostics`, `/api/delivery-metrics` | Прогоны, ошибки, задержки |
| POST | `/api/config`, `/api/start`, `/api/stop` | Настройки и управление |
| POST | `/api/events/<id>/review` | Решение оператора |
| POST | `/api/events/<id>/displayed` | Подтверждение показа |

Фильтры журнала: время, тип, камера, зона; параметры и формат запроса берутся из клиента `greathan/web/app.js`. API локальное; проверяются Host/Origin, применяются ограничения путей и тела. Это не публичный multi-tenant API.

## Хранение и метрики

В каталоге `--data`: `journal.sqlite3`, `evidence/`, `runtime_config.json`, `runs/<id>/frames.csv`, `inference.jsonl`, `summary.json`, при включении `annotated.mp4`.

Инференс измеряется на клиенте, включая подготовку/передачу/декодирование. Отдельно считаются подтверждение → журнал и подтверждение показа браузером. Временное окно до подтверждения в последнюю задержку не включается. DEMO исключается из метрик реальных событий; симуляция не заменяет проверку модели.
