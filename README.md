# GreatHanDetect — система видеоаналитики LinQ Safety

Прототип системы видеоаналитики, разработанный для хакатона LinQ. Включает интерфейс оператора, журнал событий, экспорт PDF/XLSX, анализ изображений и обнаружение сигареты возле губ на кадрах веб-камеры. **Рекомендуемый способ развёртывания — Docker Compose.** Установка и запуск не включают обучение модели.

[Демонстрационный стенд](https://linq.user-link.xyz/) · [Проверка и развёртывание](docs/REVIEWER_RU.md) · [Результаты испытаний LinQ TPU](docs/TPU_RESULTS_RU.md) · [Документация](docs/README.md)

## Быстрый запуск

Требования: Git, запущенный Docker Engine или Docker Desktop и **Docker Compose ≥ 2.20**. Проверенная платформа — Linux x86_64. На Windows используйте Docker Desktop с WSL2 и режимом контейнеров Linux. Рекомендуемые ресурсы: 4 ядра CPU, 6 ГБ оперативной памяти и 6 ГБ свободного места. Для первой сборки требуется доступ к интернету: зависимости Python/PyTorch и веса модели загружаются автоматически.

```bash
git clone https://github.com/Noizicrafty/GreatHanDetect.git
cd GreatHanDetect
docker compose up -d --build --wait
```

После запуска откройте **[http://127.0.0.1:8090/](http://127.0.0.1:8090/)**. Базовая конфигурация содержит необходимые зависимости и работает без VPN. Фиксированная версия весов опубликована в [GitHub Release](https://github.com/Noizicrafty/GreatHanDetect/releases/tag/models-2026-10-25); контрольная сумма SHA-256 проверяется при сборке. При повторной сборке используется кэш Docker.

Для автоматической проверки работоспособности выполните:

```bash
docker compose --profile check run --rm check
```

Проверка охватывает пять страниц интерфейса, ресурсы веб-камеры, PDF с кириллицей, файлы XLSX/ZIP и **выполнение модели после 26 эпох обучения на CPU**. Используются изображение с сигаретой и пустой кадр без объектов. События в журнал не добавляются. Успешное выполнение возвращает JSON с `"passed": true` и код завершения `0`. Встроенная проверка состояния контейнера контролирует доступность HTTP и наличие весов; выполнение модели проверяется отдельной командой выше.

## Функциональные возможности

1. **Трансляции:** воспроизведение предоставленных демонстрационных записей с предварительной разметкой для иллюстрации интерфейса.
2. **Анализ изображения:** «Проверить кадр» → «Использовать готовый пример». Модель YOLOv8n выполняется через PyTorch на CPU и распознаёт четыре класса: `cigarette`, `person`, `smoke`, `vape`. Результат поступает в журнал.
3. **Обработка веб-камеры:** «Веб-камера» → «Запустить». После разрешения доступа модель сопоставляет обнаруженную сигарету с областью губ. Срабатывание требует трёх последовательных совпадений в течение не менее 0,5 с. Звук и видео не записываются; выбранный кадр сохраняется отдельной кнопкой. Техническая информация доступна в разделе «О проверке».
4. **Уведомления:** подтверждение и отклонение событий с сохранением решения оператора после обновления страницы.
5. **Аналитика и отчёты:** фильтрация событий, экспорт XLSX и формирование актуального PDF по текущему журналу.

## CPU и LinQ TPU

| Режим | Требования | Выполняемая обработка |
|---|---|---|
| `docker compose up` | Docker; интернет при первой сборке | Обученная модель на CPU; после сборки работает без интернета |
| Compose с `compose.tpu.yaml` | Сеть организаторов/VPN, пакет кодирования сообщений `.whl`, брокер и программа `.tpu` в `/auto/cache/...` | Та же модель после посттренировочного квантования (PTQ) через удалённый сервис LinQ AMQP |
| Консоль `python -m greathan` | Отдельные конфигурации и файлы моделей | Конвейер обработки видео, контроля зон и отслеживания объектов; [инструкция](docs/DEPLOYMENT_RU.md) |

**Для режима TPU требуется доступ к аппаратному сервису LinQ.** Вычислитель CPU выбирается отдельно; при ошибке TPU автоматическое переключение на CPU не выполняется. Подключение существующего сервиса или дополнительного контейнера TPU описано в [инструкции по проверке и развёртыванию](docs/REVIEWER_RU.md#подключение-linq-tpu).

На общем сервисе LinQ измерены 13,58 запроса/с при последовательной отправке и 27,88 запроса/с при четырёх одновременных запросах. Полный цикл обработки через публичный веб-интерфейс составил **4,44 кадра/с** на 83 кадрах виртуальной камеры с повторяющимся изображением. Эти показатели относятся к разным участкам обработки и не определяют производительность отдельного физического чипа или качество распознавания на записях видеонаблюдения. [Методика испытаний, Jupyter Notebook и ограничения](docs/TPU_RESULTS_RU.md).

## Остановка, данные и обновление

```bash
docker compose ps
docker compose logs --tail 100 demo
docker compose down
# Обновление из чистой рабочей копии:
bash deploy/linq-demo/autodeploy.sh
```

Журнал SQLite и выбранные кадры хранятся в именованном томе `greathan-check_demo-data` и сохраняются после остановки и пересборки контейнеров. **Команда `docker compose down -v` удаляет эти данные.** Если порт занят, задайте `DEMO_PORT=8091` в `.env`, используя шаблон `.env.example`. Автоматическая проверка в [GitHub Actions](https://github.com/Noizicrafty/GreatHanDetect/actions) собирает приложение из чистой копии репозитория. Отдельный сценарий развёртывания по SSH запускается вручную и настраивается через секреты GitHub Actions; пароли в репозитории не хранятся.

## Ограничения

- Сценарии контроля касок, страховочных тросов и бега на исходных карточках помечены **DEMO**. Соответствующие модели не подключены. Результаты обученного детектора отмечаются отдельно.
- Проверяется положение сигареты у губ; факт курения требует отдельного подтверждения. Для оценки качества в производственных условиях необходимы видеозаписи и приёмочные испытания. Квантование PTQ пока снижает качество части детекций.
- Веб-камера работает на **localhost или HTTPS**. При размещении на сервере используйте HTTPS либо SSH-туннель, как описано в инструкции.
- Сохранение срабатывания веб-камеры в журнал включает отдельную CPU-проверку выбранного кадра.
- В демонстрационной версии отсутствуют авторизация и разграничение доступа пользователей. По умолчанию порт доступен только через локальный интерфейс. Публичное размещение требует контроля доступа и настройки обратного прокси-сервера.
